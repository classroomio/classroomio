When a request fails, the API returns an HTTP error status and a JSON body that explains what went wrong.

## Error format

```json
{
  "success": false,
  "error": "Human-readable message",
  "code": "MACHINE_READABLE_CODE",
  "field": "optional.field.path"
}
```

- `error` is meant for people. Don't match on it, since the wording can change.
- `code` is stable. Use it in your code to decide what to do.
- `field` names the input that failed. It is present on validation errors and on conflicts that name a field (e.g. `SITENAME_EXISTS` with `field: 'siteName'`).

## HTTP status codes

| Status | Meaning |
| --- | --- |
| `200` / `201` | The request worked |
| `400` | The request body or query is invalid |
| `401` | The credential (API key or OAuth token) is missing, invalid, expired, or revoked |
| `403` | The credential can't call this endpoint — missing scope, or a plan without API access |
| `404` | The resource doesn't exist, or belongs to another organization |
| `409` | The request conflicts with the resource's current state |
| `429` | Too many requests. See [Rate limits](/api/rate-limits) |
| `500` | Something went wrong on our side |
| `503` | A safety check, such as a rate limit, couldn't run. Retry later |

## Common errors

### Invalid API key or token

Status `401`

```json
{
  "success": false,
  "error": "Invalid organization API key",
  "code": "UNAUTHORIZED"
}
```

**Fix:** Check that the header is `Authorization: Bearer <credential>` and that it hasn't been rotated, revoked, or — for an OAuth access token — expired. Access tokens last 10 minutes; refresh the token and retry. See [Authentication](/api/authentication).

### Missing scope

Status `403`

```json
{
  "success": false,
  "error": "Automation key is missing required scopes",
  "code": "FORBIDDEN"
}
```

**Fix:** You're using a key that can't call this endpoint, usually an MCP key or a connected MCP app. Use an API key (`cio_api_...`) instead. An OAuth access token that lacks the route's scope fails the same way; reconnect the app and grant that scope.

An OAuth connection, such as Zapier, gets `INSUFFICIENT_SCOPE` instead, with the missing scope in `requiredScope`:

```json
{
  "success": false,
  "error": "This connection was not granted the course:member:write permission",
  "code": "INSUFFICIENT_SCOPE",
  "requiredScope": "course:member:write"
}
```

**Fix:** Reconnect the app and grant the permission. A connection made read-only can't call write endpoints.

### Resource not found

Status `404`

```json
{
  "success": false,
  "error": "Course not found",
  "code": "COURSE_NOT_FOUND"
}
```

**Fix:** Check the ID, and that the resource belongs to the organization your key is for.

### Invalid parameters

Status `400`

```json
{
  "success": false,
  "error": "email: Invalid email address",
  "code": "VALIDATION_ERROR",
  "field": "email"
}
```

**Fix:** Correct the input named in `field`. The endpoint's page lists every parameter and its type.

### Rate limit exceeded

Status `429`. The body depends on which limit you hit. The per-key request limit uses its own shape with `retryAfter`. The MCP usage limit uses the standard format with `code` `AUTOMATION_RATE_LIMIT_EXCEEDED`, and the course invite limit on `POST /courses/{courseId}/enrollments` uses it with `code` `COURSE_INVITE_RATE_LIMIT_EXCEEDED`. See [Exceeding the limit](/api/rate-limits#exceeding-the-limit) and [Course invites](/api/rate-limits#course-invites).

### Rate limit unavailable

Status `503`, with `code` `RATE_LIMIT_UNAVAILABLE`. Creating course invites is refused while the rate limiter can't be checked, rather than letting invites through unlimited.

**Fix:** Retry after a short wait.

### Staff can't be enrolled

Status `409`, with `code` `STAFF_CANNOT_ENROLL`, from `POST /courses/{courseId}/enrollments` when the email belongs to an admin or tutor in your organization.

**Fix:** Add admins and tutors to the course from the dashboard.
