When a request fails, the API returns an HTTP error status and a JSON body that explains what went wrong.

## Error format

```json
{
  "success": false,
  "error": "Human-readable message",
  "code": "MACHINE_READABLE_CODE",
  "field": "optional.field.path"
}
```

- `error` is meant for people. Don't match on it, since the wording can change.
- `code` is stable. Use it in your code to decide what to do.
- `field` names the input that failed. It is present on validation errors and on conflicts that name a field (e.g. `SITENAME_EXISTS` with `field: 'siteName'`).

## HTTP status codes

| Status        | Meaning                                                                                                                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `200` / `201` | The request worked                                                                                                                                           |
| `400`         | The request body or query is invalid                                                                                                                         |
| `401`         | The credential (API key or OAuth token) is missing, invalid, expired, or revoked                                                                             |
| `403`         | The credential can't call this endpoint — missing scope, read-only connection, or a plan without API access                                                  |
| `404`         | The resource doesn't exist, or belongs to another organization                                                                                               |
| `409`         | The request conflicts with the resource's current state                                                                                                      |
| `413`         | The declared upload size is over the limit                                                                                                                   |
| `429`         | Too many requests. See [Rate limits](/api/rate-limits)                                                                                                       |
| `500`         | Something went wrong on our side                                                                                                                             |
| `503`         | A safety check, such as a rate limit, couldn't run. A fail-closed analytics, reminder, email-template test, or course-invite request is refused; retry later |

## Common errors

### Invalid API key or token

Status `401`

```json
{
  "success": false,
  "error": "Invalid organization API key",
  "code": "UNAUTHORIZED"
}
```

**Fix:** Check that the header is `Authorization: Bearer <credential>` and that it hasn't been rotated, revoked, or — for an OAuth access token — expired. Access tokens last 10 minutes; refresh the token and retry. See [Authentication](/api/authentication).

### Missing scope

Status `403`

```json
{
  "success": false,
  "error": "Automation key is missing required scopes",
  "code": "FORBIDDEN"
}
```

**Fix:** You're using an MCP key (`cio_mcp_...`) that can't call this endpoint. Use an API key (`cio_api_...`) instead.

An OAuth connection, such as Zapier, gets `INSUFFICIENT_SCOPE` instead, with the missing scope in `requiredScope`:

```json
{
  "success": false,
  "error": "This connection was not granted the course:member:write permission",
  "code": "INSUFFICIENT_SCOPE",
  "requiredScope": "course:member:write"
}
```

**Fix:** Reconnect the app and grant the permission. A connection made read-only can't call endpoints whose scopes change workspace data, but it keeps `webhook:subscription:write` so it can still manage the subscriptions its triggers need.

### Resource not found

Status `404`

```json
{
  "success": false,
  "error": "Course not found",
  "code": "COURSE_NOT_FOUND"
}
```

**Fix:** Check the ID, and that the resource belongs to the organization your key is for.

### Invalid parameters

Status `400`

```json
{
  "success": false,
  "error": "email: Invalid email address",
  "code": "VALIDATION_ERROR",
  "field": "email"
}
```

**Fix:** Correct the input named in `field`. The endpoint's page lists every parameter and its type.

### Rate limit exceeded

Status `429`. The body depends on which limit you hit. The per-key request limit uses its own shape with `retryAfter`. The MCP usage limit uses the standard format with `code` `AUTOMATION_RATE_LIMIT_EXCEEDED`, and the course invite limit on `POST /courses/{courseId}/enrollments` uses it with `code` `COURSE_INVITE_RATE_LIMIT_EXCEEDED`. See [Exceeding the limit](/api/rate-limits#exceeding-the-limit) and [Course invites](/api/rate-limits#course-invites).

### Rate limit unavailable

Status `503`, with `code` `RATE_LIMIT_UNAVAILABLE`. Creating course invites is refused while the rate limiter can't be checked, rather than letting invites through unlimited.

**Fix:** Retry after a short wait.

### Staff can't be enrolled

Status `409`, with `code` `STAFF_CANNOT_ENROLL`, from `POST /courses/{courseId}/enrollments` when the email belongs to an admin or tutor in your organization. `POST /cohorts/{cohortId}/members` reports the same code for that entry in its `errors[]` list when a student entry's email or profile belongs to an admin or tutor.

**Fix:** Add admins and tutors to the course from the dashboard, or to the cohort with the tutor role.

### Rate limit unavailable

Status `503` with `code` `RATE_LIMIT_UNAVAILABLE`. The Academy analytics query, analytics snapshot, overdue-goal reminder, email-template test-email, and course-invite limiters are fail-closed: when Redis cannot be reached to check the budget, the request is refused instead of going through. Retry once Redis is reachable again. See [Fail-closed limits](/api/rate-limits#fail-closed-limits).

### Organization member is archived

Status `409`, with `code` `ORG_MEMBER_ARCHIVED`, from `POST /courses/{courseId}/enrollments` and `POST /courses/{courseId}/members` when the email belongs to an archived organization member. Archived members cannot gain a course seat until they are restored. `POST /cohorts/{cohortId}/members` reports the same code for that person in its `errors[]` list instead of failing the whole request.

**Fix:** Restore the member from **Audience** with the **Archived** status filter, then call the endpoint again.

### Member has not joined

Status `409`, with `code` `MEMBER_NOT_JOINED`, from `POST /courses/{courseId}/members` when the email belongs to a pending organization member who has not accepted their invite yet.

**Fix:** Call `POST /courses/{courseId}/enrollments` instead. It adds the course to the member's organization invite, and they join the course when they accept. This works for students only; a pending admin or tutor must accept their team invite first.

### Already in the course

Status `409`, with `code` `COURSE_MEMBER_EXISTS`, from `POST /courses/{courseId}/members` when the person is already a member of the course.

**Fix:** No action is needed. Look the member up with `GET /courses/{courseId}/members` if you need their id.

### Email linked to another account

Status `409`, with `code` `ORG_MEMBER_EMAIL_LINKED_TO_OTHER_ACCOUNT` and `field: 'email'`, when the email already belongs to a different account in your organization. It can happen when two requests add the same person at the same time.

**Fix:** Retry the request. If it fails again, check the person in **Audience**.

### No student seats left

Status `403`, with `code` `UPGRADE_REQUIRED`, from `POST /courses/{courseId}/enrollments` when inviting a new student would pass your plan's student limit. `POST /cohorts/{cohortId}/members` reports the same code for that person in its `errors[]` list instead of failing the whole request.

**Fix:** Free a seat by revoking unused invitations or archiving students, or upgrade the plan. See [Understand usage and plan limits](https://classroomio.com/help/get-started/understand-usage-and-plan-limits).
