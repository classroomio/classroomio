ClassroomIO is an OAuth 2.1 authorization server. A platform that cannot hold a long-lived secret registers itself, sends a workspace admin through a consent screen, and receives short-lived tokens it can use with the public API and the remote MCP endpoint.

Use [Connect an MCP client](/developers/mcp/setup) when you run the client yourself; it signs in the same way. To connect Claude or ChatGPT you do not need this page: see [Connect from Claude or ChatGPT](/developers/mcp/remote).

## What the admin sees

1. The platform sends the admin to ClassroomIO to sign in.
2. The consent screen names the platform, lists the permissions in plain language, lets the admin pick the workspace the platform may act on (if they administer more than one), and shows where approval will send the browser. When the platform asks for write scopes, the admin can turn off changes to grant read-only access: every scope that changes workspace data is dropped, and `webhook:subscription:read` and `webhook:subscription:write` are kept. Clients that send `prompt=consent` (as the ClassroomIO Zapier app does) show the screen on every authorization request, even when the admin approved the platform before; other clients skip the screen when the stored grant already covers the requested scopes, and a request with `prompt=none` fails instead of showing UI (`login_required` when signed out, `consent_required` when approval is still needed, `interaction_required` while workspace selection is pending). What the admin approves replaces the platform's earlier grant in that workspace: approving read-only access narrows it. Access tokens issued earlier with a write scope are rejected from then on; the first such token presented to the API also deletes the grant's stale access and refresh tokens, so refresh tokens stop working at that point too. Read the `scope` field of the token response to see what was granted.
3. After approval the platform receives an authorization code and exchanges it for tokens.

Only workspace admins can connect a platform. Access follows the admin's role: if they stop being an admin of that workspace, the platform loses access and its grant is deleted.

## Discovery

Fetch the server metadata instead of hard-coding endpoints:

```
https://app.classroomio.com/.well-known/oauth-authorization-server
```

The same document is also served at `/.well-known/openid-configuration` and under `/api/auth/.well-known/`, and any origin can read it. For a self-hosted installation, use your dashboard origin. The metadata lists the authorization, token, registration and revocation endpoints, the signing keys (`jwks_uri`) and `scopes_supported`. It sets `authorization_response_iss_parameter_supported` to `true`, so check that the `iss` parameter on the authorization response matches the issuer.

## Register a client

Clients register themselves with [Dynamic Client Registration](https://datatracker.ietf.org/doc/html/rfc7591) at `registration_endpoint`. Registration is rate limited, and every registered client is untrusted: it cannot call the public API until an administrator grants it access.

Trusted clients, such as ClassroomIO's native Zapier integration, are pre-registered confidential clients configured by ClassroomIO.

### Trusted clients

Two API environment variables configure first-party integrations. Trusted clients are registered by an operator running a script on the server (`pnpm --filter @cio/db oauth:register-client`), never by the third-party platform itself:

| Variable                   | Purpose                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OAUTH_TRUSTED_CLIENT_IDS` | Comma-separated OAuth client IDs treated as first-party; they cannot be modified through the dynamic client CRUD endpoints. Leave empty unless deploying ClassroomIO's own integration. |
| `ZAPIER_OAUTH_CLIENT_ID`   | The client ID of ClassroomIO's Zapier OAuth client, used to identify Zapier grants.                                                       |

Store only client IDs issued to ClassroomIO's own integrations in `OAUTH_TRUSTED_CLIENT_IDS`. Third-party clients registered through dynamic registration must stay untrusted.

Register a third-party platform with dynamic client registration (this path always creates an untrusted client):

```bash
curl -X POST https://app.classroomio.com/api/auth/oauth2/register \
  -H "Content-Type: application/json" \
  -d '{
    "client_name": "My Platform",
    "redirect_uris": ["https://platform.example.com/callback"],
    "token_endpoint_auth_method": "none",
    "grant_types": ["authorization_code", "refresh_token"],
    "response_types": ["code"]
  }'
```

Redirect URIs are matched exactly. Use HTTPS outside local development.

## Authorize

Send the admin to `authorization_endpoint` with these parameters:

| Parameter               | Value                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `response_type`         | `code`                                                                                                |
| `client_id`             | The ID returned at registration                                                                       |
| `redirect_uri`          | One of the registered redirect URIs                                                                   |
| `scope`                 | Space-separated [scopes](#scopes). Add `offline_access` to receive a refresh token                    |
| `code_challenge`        | PKCE challenge. Only `S256` is accepted and PKCE is required                                          |
| `code_challenge_method` | `S256`                                                                                                |
| `resource`              | The API the token is for: `https://api.classroomio.com/public-api/v1` or the remote MCP endpoint URL |
| `state`                 | A random value you verify on the callback                                                             |

The `resource` parameter is required. Tokens are issued for that resource only and are rejected by everything else.

Exchange the returned `code` at `token_endpoint` with the `code_verifier`, the same `redirect_uri` and the same `resource`.

## Call the API

Send the access token as a bearer token:

```bash
curl https://api.classroomio.com/public-api/v1/team \
  -H "Authorization: Bearer <access_token>"
```

OAuth tokens use the same public API routes and the same scopes as automation keys, and they require the same plan access. They are subject to the same rate limit — one 100-requests-per-minute budget per OAuth connection. The ClassroomIO Zapier integration follows the same rule; it has no separate per-plan quotas. A request fails with `401` when the token is expired or revoked, and with `403` and code `INSUFFICIENT_SCOPE` when the token does not carry the scope the route needs; `requiredScope` names the missing scope.

## Token lifetime

- Access tokens expire after 10 minutes.
- Refresh tokens are issued when you request `offline_access` and last 90 days. Each refresh returns a new refresh token and replaces the previous one. The previous token still works for 60 seconds, so refreshes running in parallel don't fail. Reusing it after that is treated as theft and invalidates the newer refresh tokens too, so a replayed token cannot be used quietly.
- A grant stays valid after the admin signs out of the dashboard. It ends when the admin removes the app, loses the admin role, or the grant is revoked.

You can also revoke a token yourself at `revocation_endpoint` ([RFC 7009](https://datatracker.ietf.org/doc/html/rfc7009)).

## Scopes

Tokens carry the same scopes as automation keys. `public_api:*` is never granted through OAuth.

| Area                      | Scopes                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Courses                   | `course:read`, `course:write`, `course:tag:write`                                                                |
| Exercises                 | `course:exercise:read`, `course:exercise:write`                                                                  |
| Course members            | `course:member:read`, `course:member:write`, `course:student:write`                                              |
| Certificates              | `course:certificate:read`, `course:certificate:write`                                                            |
| Submissions and marks     | `course:submission:read`, `course:submission:write`                                                              |
| Cohorts                   | `cohort:read`, `cohort:write`                                                                                    |
| Audience                  | `audience:read`, `audience:write`                                                                                |
| Team                      | `team:read`, `team:write`                                                                                        |
| Workspace                 | `organization:read`, `organization:write`, `organization:domain:write`                                           |
| Analytics and media       | `analytics:read`, `media:write`                                                                                  |
| Webhook subscriptions     | `webhook:subscription:read`, `webhook:subscription:write`                                                        |

## Receive events (REST hooks)

ClassroomIO's managed REST hook subscriptions are reserved for the first-party ClassroomIO Zapier OAuth client. The platform accepts only callback URLs on `hooks.zapier.com`, so an arbitrary OAuth application cannot use this endpoint to register a receiver. Other integrations should either poll the public API or have an organization administrator configure a [webhook](/developers/webhooks) in the dashboard.

### Subscribing to an event

With the ClassroomIO Zapier OAuth client, request the `webhook:subscription:write` scope and call `POST /public-api/v1/webhooks/subscriptions`:

```bash
curl -X POST https://api.classroomio.com/public-api/v1/webhooks/subscriptions \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "targetUrl": "https://hooks.zapier.com/hooks/catch/123456/abcdef/",
    "eventType": "course.completed",
    "courseId": "98e6e798-f0bd-4f9d-a6f5-ce0816a4f97e"
  }'
```

- `targetUrl`: The HTTPS destination that receives events. Managed subscriptions require a `hooks.zapier.com` host; the URL must respond with a `2xx` status within 10 seconds.
- `eventType`: The webhook event to listen for (such as `course.member.added`, `course.completed`, or `course.certificate.issued`).
- `courseId` or `cohortId` (optional): Filter events to a specific course or cohort.

The response returns `201 Created` (or `200 OK` if the target URL is already subscribed to that event) with the subscription ID and a signing secret:

```json
{
  "success": true,
  "data": {
    "id": "6f1c2b9e-3a4d-4e8f-9b7a-2c5d1e0f8a3b",
    "eventType": "course.completed",
    "targetUrl": "https://hooks.zapier.com/hooks/catch/123456/abcdef/",
    "courseId": "98e6e798-f0bd-4f9d-a6f5-ce0816a4f97e",
    "cohortId": null,
    "secret": "whsec_...",
    "createdAt": "2026-10-31T12:00:00.000Z"
  }
}
```

Every delivery to `targetUrl` is signed using the subscription's secret and includes both standard `X-Cio-Signature-256` HMAC headers and [Standard Webhooks](https://www.standardwebhooks.com) headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`). See [Verify the signature](/developers/webhooks#verify-the-signature).

### Listing sample events

During setup and field mapping, clients with the `webhook:subscription:read` scope can fetch representative event payloads by calling `GET /public-api/v1/webhooks/samples`:

```bash
curl "https://api.classroomio.com/public-api/v1/webhooks/samples?eventType=course.completed" \
  -H "Authorization: Bearer <access_token>"
```

This returns up to three recent real event payloads from the workspace, or the documented event example if no events of that type have occurred yet.

### Unsubscribing

When a workflow is turned off or deleted, remove the subscription with `DELETE /public-api/v1/webhooks/subscriptions/:subscriptionId`:

```bash
curl -X DELETE https://api.classroomio.com/public-api/v1/webhooks/subscriptions/6f1c2b9e-3a4d-4e8f-9b7a-2c5d1e0f8a3b \
  -H "Authorization: Bearer <access_token>"
```

### Lifecycle

- Subscriptions are managed per OAuth grant: if the admin revokes access or loses their admin role, all subscriptions created by that app are deleted immediately.
- A subscription is also deleted when its target URL answers `410 Gone`, or when a delivery finds that its grant no longer belongs to an active admin. ClassroomIO doesn't email admins about failing managed subscriptions.
- Managed subscriptions do not count toward the workspace's manual 20-endpoint webhook cap.
- A subscription that ClassroomIO auto-disabled after repeated delivery failures is reactivated, with its failure count reset, the next time the app subscribes the same target URL.

## Manage connected apps

Admins see connected AI platforms in **Automation → MCP → Connected apps**, and Zapier connections in **Automation → Zapier**, with who connected each one and when. Removing an app deletes its grant, tokens, and any webhook subscriptions it holds, stopping access immediately.
