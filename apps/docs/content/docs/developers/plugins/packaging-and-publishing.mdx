`cio-plugin` has five commands.

| Command | Purpose |
| --- | --- |
| `cio-plugin create <directory>` | Create a Vite-based plugin starter. |
| `cio-plugin build [path] [--all]` | Validate, compile, and produce a deterministic archive. `npm run pack` is the scaffolded alias. |
| `cio-plugin dev [path] --org <organization-id>` | Build and install a development release into one local organization. `npm run seed` is the scaffolded alias. |
| `cio-plugin publish [path]` | Build, upload to quarantine, and submit for review. |
| `cio-plugin status <submission-id>` | Check a review result. |

## Create a plugin

```bash
npx cio-plugin create reading-timer \
  --id com.example.reading-timer \
  --name "Reading timer" \
  --publisher "Example"
cd reading-timer
npm install
```

The generated project has conventional Vite `npm run dev` and `npm run build` scripts. Use the
`cio-plugin` CLI explicitly when you need to install a packaged development release or create an
immutable artifact. The generated `pack` and `seed` scripts reserve those names for ClassroomIO
workflows without taking over npm's standard `build` and `dev` scripts.

## Publisher credentials

Publishing uses a scoped organization API key. The key secret is the value assigned to
`CLASSROOMIO_PLUGIN_TOKEN`; it is shown only once when created.

For the current v1 flow, a developer needs a ClassroomIO account and access to an organization.
An organization administrator creates an API key with exactly the `plugin:publish` scope and gives
the developer the secret through a secure channel. Do not use `PRIVATE_SERVER_KEY` or a broad
`public_api:*` key.

The key's organization is the credential owner. It is not the organization where a public plugin
will eventually be installed. Public marketplace publishing does not require `CLASSROOMIO_ORG_ID`.

The CLI currently requires `CLASSROOMIO_ORG_ID` only for `dev` (or its `npm run seed` alias), because local development must
install into one explicit organization. The dashboard form for custom automation scopes is still a
pending product surface; until it is available, an operator must create the scoped key through the
approved administrative API/tooling.

## Local development

Start the ClassroomIO API locally, create a scoped publisher token, then target exactly one organization:

```bash
export CLASSROOMIO_API_URL=http://localhost:3002
export CLASSROOMIO_PLUGIN_TOKEN=<publisher-token>
export CLASSROOMIO_ORG_ID=<organization-id>
npm run dev
```

`npm run dev` starts the plugin's Vite server for standalone UI development. It does not install the
plugin into ClassroomIO.

To validate, package, and install the development release in the selected organization, stop the
Vite server and run:

```bash
npm run seed -- --org "$CLASSROOMIO_ORG_ID"
```

The API validates the archive, writes its files to `PLUGIN_ARTIFACTS_PATH`, and updates the named
organization's installation. It never uses a server master key and is disabled in production.

## Build

```bash
npm run build
npm run pack
```

`npm run build` compiles the UI. `npm run pack` invokes `cio-plugin build`, which validates `plugin.json`, checks the generated
assets, and creates a deterministic archive beneath `.plugin-artifacts/`. The SHA-256 digest
identifies the exact artifact that will be submitted.

## Submit for review

```bash
export CLASSROOMIO_API_URL=https://api.classroomio.com
export CLASSROOMIO_PLUGIN_TOKEN=<publisher-token>
npm run publish
```

The API creates a submission and returns a short-lived object-storage upload URL. The CLI uploads the archive directly to the private quarantine bucket, then tells the API to verify it. The archive is checked for its digest, manifest, unsafe paths, links, and host imports before a review record is created.

ClassroomIO namespace plugins (`com.classroomio.*`) require a platform-admin publisher token. All other plugins use the same review pipeline.

## Review and release

Reviewers inspect a quarantined submission through the reviewer API and the configured review origin, then either reject it with notes or approve it. Approval copies the verified assets and archive from quarantine to `PLUGIN_ASSET_BUCKET`; production loads them only from `PLUGIN_ASSET_ORIGIN` under the verified content digest. Quarantine objects are never served by the production CDN.

The API currently provides the reviewer queue, submission details, preview URL, and approve/reject actions. A dashboard reviewer screen and the Cloudflare review-origin worker are deployment surfaces that must be provided by the host environment; `PLUGIN_REVIEW_ORIGIN` must resolve a reviewer-authenticated preview for the submission ID.

The planned reviewer dashboard is platform-admin-only. It will show the review queue, manifest,
digest, permissions, validation results, quarantined preview, review notes, and immutable approval
history. Organization administrators and plugin publishers cannot approve releases.

## Production storage setup

Use separate private storage locations for quarantine and approved artifacts:

| Location | API access | Browser access |
| --- | --- | --- |
| `PLUGIN_QUARANTINE_BUCKET` | API read; presigned upload only | Review origin only, authenticated |
| `PLUGIN_ASSET_BUCKET` | API promotion write | Production CDN read-only |

The review and production origins must be separate. The production CDN must never read from the
quarantine bucket. Configure the review worker to validate the submission ID, authenticate the
reviewer, apply restrictive CSP/CORS headers, and expose only the quarantined preview. Configure
the production worker to serve only approved, digest-qualified keys.

## Complete lifecycle

1. `create` scaffolds the project, `npm run build` compiles the UI, and `npm run pack` invokes `cio-plugin build` to produce a deterministic archive.
2. `npm run seed` invokes `cio-plugin dev` and sends that archive to the local development endpoint, where it is validated, unpacked under `PLUGIN_ARTIFACTS_PATH`, registered as a private development version, and installed in one organization.
3. `publish` creates a database intent, receives a short-lived R2/S3 presigned upload URL, uploads the archive directly to quarantine, and calls `complete`.
4. `complete` reads the quarantine object, verifies its digest and manifest, rejects unsafe paths/links/host imports, and moves the submission to `in_review`.
5. A platform reviewer uses the reviewer queue and preview origin. Rejection records notes and leaves the artifact quarantined; approval copies every verified file to the immutable production bucket and marks the version approved.
6. The catalog exposes only approved versions. Organization administrators install an approved version, and the host serves its assets from the digest-qualified production CDN URL.

The publisher token is never a server master key. `PRIVATE_SERVER_KEY` remains an internal dashboard/API credential and must not be used by plugin developers or CI.

## Environment variables

### CLI

| Variable | Required by | Meaning |
| --- | --- | --- |
| `CLASSROOMIO_API_URL` | `dev`, `publish`, `status` | API origin; defaults to `http://localhost:3002`. |
| `CLASSROOMIO_PLUGIN_TOKEN` | `dev`, `publish`, `status` | Scoped publisher token. |
| `CLASSROOMIO_ORG_ID` | `dev` | Local target organization; `--org` overrides it. |

### API host

| Variable | Environment | Meaning |
| --- | --- | --- |
| `PLUGIN_API_TOKEN_SECRET` | production | Independent secret (at least 32 characters) used to sign plugin backend access tokens. Never expose it to plugin UI or CLI users. |
| `PLUGIN_ARTIFACTS_PATH` | local | Filesystem root for development artifacts. |
| `PLUGIN_QUARANTINE_BUCKET` | local and production publishing | Private R2/S3 bucket for submitted archives. |
| `PLUGIN_REVIEW_ORIGIN` | production review | Authenticated reviewer-only preview origin. |
| `PLUGIN_ASSET_BUCKET` | production | Bucket for approved assets. |
| `PLUGIN_ASSET_ORIGIN` | production | CDN origin for approved assets. |

`PRIVATE_SERVER_KEY` is an API-host internal-service credential. It is not a plugin CLI credential and must never be placed in a plugin repository or CI publishing environment.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `Local development requires --org` | `dev`/`seed` has no target organization | Set `CLASSROOMIO_ORG_ID` or pass `--org`. |
| `API key is missing plugin:publish scope` | The token is an ordinary API key | Create or rotate a key with only `plugin:publish`. |
| `PLUGIN_QUARANTINE_BUCKET is required` | The production submission bucket is unset | Configure the private quarantine bucket on the API. |
| Digest mismatch | The archive changed after the intent was created | Run `build` again and publish the resulting archive. |
| Manifest mismatch or forbidden import | The packaged `plugin.json` or source violates the release rules | Fix the manifest/source and rebuild. |
| Preview fails but review succeeds | Review-origin worker, authentication, or CORS/CSP is misconfigured | Check the review origin and keep it separate from production assets. |
| Approved plugin assets fail to load | CDN origin, bucket policy, or response headers are incorrect | Verify the digest-qualified production key and CDN response headers. |
