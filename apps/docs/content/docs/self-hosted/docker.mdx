Run ClassroomIO anywhere Docker runs. One script manages the entire lifecycle: you copy it,
run it, and pick a number. New to self-hosting? Start with
[Self-hosting 101](/self-hosted/101) to see what you're deploying.

![Selfhost ClassroomIO](/docs/selfhost-classroomio.webp)

## Prerequisites

- Docker installed and running (Compose v2 or the legacy `docker-compose` both work).
- A server that meets the [requirements](/self-hosted#server-requirements) (8 GB RAM recommended).

## Quick start

<Steps>
<Step>
### Get the script

```zsh title="Terminal"
mkdir classroomio && cd classroomio
curl -fsSLO https://classroomio.com/classroomio.sh
chmod +x classroomio.sh
```
</Step>
<Step>
### Run it and pick Install

```zsh title="Terminal"
./classroomio.sh
```

Choose **1) Install**. The script downloads the compose file, creates `.env` from the template,
generates the auth secrets and MinIO credentials for you, then pulls the images and starts the
stack. Re-running Install is safe: it never overwrites an existing `.env` or compose file.
</Step>
<Step>
### Edit the required values

Everything else is auto-generated or defaulted. For a real deployment, set only:

```zsh title=".env"
CIO_VERSION=1.0.0                            # pin a release for production
DASHBOARD_ORIGIN=https://app.yourdomain.com  # your public https:// URL
POSTGRES_PASSWORD=<strong password>          # required in production
SMTP_HOST=                                   # email — signup, resets, invites
SMTP_PORT=
SMTP_USER=
SMTP_PASSWORD=
SMTP_SENDER=
```

Then apply: `./classroomio.sh restart`

:::warning[Changing `POSTGRES_PASSWORD` after Install does nothing on its own]
Postgres only applies `POSTGRES_PASSWORD` the first time it initializes its data volume. If
you're editing `.env` after Install has already run, see [rotating it after
install](/self-hosted/configuration/secrets#rotating-postgres_password-after-install) —
just restarting/recreating containers will break the DB connection instead of fixing it.
:::
</Step>
</Steps>

The dashboard is at http://localhost:3082, the API at http://localhost:3081, and the MinIO console
at http://localhost:9001 (credentials are in your `.env`).

:::warning[Pin `CIO_VERSION` in production]
The default tags track moving builds: `latest` changes on every merge to `main`. Pin an exact
release (e.g. `CIO_VERSION=1.4.2`) so an upstream merge can never change your deployment
unannounced. The script warns you about this too. See
[Versions & upgrades](/self-hosted/configuration/versions).
:::

:::note[Serving on a real domain?]
Use an `https://` origin: session cookies are `Secure`, so
[login silently fails over plain HTTP](/self-hosted#https-is-required-in-production).
:::

## The menu

| Option | What it does |
|--------|--------------|
| 1 Install | First-time setup: fetch files, create `.env`, generate secrets, pull and start. |
| 2 Start | Start the stack (also fills in any missing secrets first). |
| 3 Stop | Stop containers. Data volumes are kept. |
| 4 Restart | Restart containers, e.g. after editing `.env`. |
| 5 Upgrade | **Backs up first**, then pulls newer images and restarts. |
| 6 View logs | Follow logs for all services or one (`./classroomio.sh logs api`). |
| 7 Backup | Dump Postgres and archive the MinIO volume into `./backups/`. See [Backups](/self-hosted/backups). |

Every option is also a subcommand (`./classroomio.sh upgrade`), so you can script or cron it.

<Expandable title="Build from source instead of pulling images">

To run local code changes, clone the repo and use the same script with `--build`
(needs `git` and ~8 GB RAM for the dashboard build):

```zsh title="Terminal"
git clone https://github.com/classroomio/classroomio.git
cd classroomio
cp .env.example .env
./classroomio.sh start --build
```

Without `--build` the script pulls the published `classroomio/*` images at your `CIO_VERSION`,
which is the faster default. `--no-minio` excludes the bundled MinIO if you use external
[S3/R2 storage](/self-hosted/configuration/storage).

</Expandable>

## Configuration reference

Docker self-hosting uses a single root `.env` file: every compose command reads it via
`--env-file .env`, and the compose file itself tracks `main` (it's just the stack topology;
`CIO_VERSION` pins the app images).

<Expandable title="Common .env values">

```zsh title=".env"
CIO_VERSION=1.0.0                 # pin a release (not "latest") so upgrades are deliberate
DASHBOARD_ORIGIN=https://app.yourdomain.com
BETTER_AUTH_SECRET=               # auto-generated by the script if left blank
PRIVATE_SERVER_KEY=               # auto-generated; must be identical in api and dashboard
POSTGRES_PASSWORD=<strong password>
# Email (required for signup/reset/invites)
SMTP_HOST=
SMTP_PORT=
SMTP_USER=
SMTP_PASSWORD=
SMTP_SENDER=
```

See [`.env.example`](https://github.com/classroomio/classroomio/blob/main/.env.example) for the
full annotated template.

</Expandable>

## Upgrading

Run `./classroomio.sh upgrade`: it backs up Postgres and MinIO first, then pulls the images at
your (possibly newly pinned) `CIO_VERSION` and restarts. Rollback = set `CIO_VERSION` back and
upgrade again. Details: [Versions & upgrades](/self-hosted/configuration/versions).

Something not working? See [Troubleshooting](/self-hosted/troubleshooting).
