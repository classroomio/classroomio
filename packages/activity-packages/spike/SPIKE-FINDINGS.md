# Phase 0 spike findings

Spike player: `spike/player/server.mjs` (scorm-again `3.4.6`, pinned). Fixtures and baselines: `test/fixtures/README.md`. Domain, DNS and license-server items live in `prd/scorm-support/v2/phase-0-ops-content-domain-and-license.md` and are not repeated here.

## Setup

- Content origin `http://content.localhost:3002`, vendor origin `http://127.0.0.1:3003`. Verified both serve: index, `/play`, `/files`, `/stub/commit` return 200, path traversal returns 404, stub answers `{ "result": true, "errorCode": 0 }`.
- Player settings: `autocommit` true, `autocommitSeconds` 30, `lmsCommitUrl` `/stub/commit`, `sendFullCommit` false, `includeCommitSequence` true, `selfReportSessionTime` false, `logLevel` 2. `autoCompleteLessonStatus` and `mastery_override` stay at their defaults (false).
- Each `scorm-again` import is the versioned ESM build (`dist/esm/scorm12.js`, `dist/esm/scorm2004.js`), confirmed present in the published `3.4.6` tarball.

## Answers

1. **Synchronous commit is smooth enough; asynchronous mode is not worth it.** scorm-again v3 commits synchronously by default and documents `useAsynchronousCommits` as not SCORM-compliant that may cause data loss. The spike stays on the default. The teardown helpers (`pendingCommitCount`, `whenCommitsSettled`) only matter for async players and are not used.
2. **Changed-fields commits merge cleanly and the Terminate beacon stays under budget.** `sendFullCommit: false` sends only fields with values. The server merges each numbered commit over the stored CMI and ignores stale sequences. Beacons are capped at 64 KiB (MDN; W3C Beacon; Edge and Firefox enforce 64 KB per beacon, Chrome a 64 KB quota across beacons in the navigation context). Fixture suspend data is 7–18 chars; the risk is a vendor package whose suspend data alone approaches 64 KiB, which Phase 5 measures against Storyline and Rise exports. A beacon that returns false must fall back to `fetch` with `keepalive`, never to a dropped save.
3. **Long 1.2 suspend data is stored whole; client acceptance is still unprobed.** The 4,096-char SPM is confirmed (ADL conformance, Moodle threads), and the PRD stores suspend data whole without truncation. The spike stub accepts any length, but no browser run has pushed >4,096 chars through scorm-again's `LMSSetValue` yet. PR 10 feeds a 10 KB suspend value through the spike player and records whether the client returns error 351/405 before the server change lands.
4. **The unload opt-out works, but the player does not depend on it.** Chrome removed `unload` handlers by default through milestones 146–154 (100% at 154, September 2026); `Permissions-Policy: unload=self` opts a page back in, and MDN confirms the mechanism. Content-host responses can send it, but the player flushes on `pagehide` with a beacon when the package has not terminated, so old `onunload` packages save either way.
5. **New-window mode falls back on phones; resume is server-side.** Safari blocks pop-ups by default and opens background tabs it may discard, which is why new-window mode falls back to the course page on phones. Resume after reload works because launch fetches the saved CMI and calls `loadFromJSON` before the package starts. Device-farm confirmation (Safari iOS, Chrome Android, embedded and new-window) is a PR 15 compatibility-matrix item.
6. **scorm-again applies neither LMS rule by default, so the server applies each once.** With the spike defaults, `autoCompleteLessonStatus: false` leaves a never-set 1.2 status as `incomplete`, and `mastery_override: false` never overrides from the mastery score. The server's `applyLmsRules` therefore owns all three PRD rules: 1.2 `LMSFinish` with no status records `completed`; the unit's `masteryScore` decides passed/failed from the raw score; 2004 threshold and passing-score evaluation run on Terminate. Both client flags stay false forever. One nuance: scorm-again still surfaces a client-computed completion status to the package via `GetValue`; the server never trusts it and re-derives the outcome from the stored CMI plus the unit's pass marks on every commit.
7. **1.2 resume after a non-suspend exit works because the server replays state.** The player loads the stored CMI with `loadFromJSON` before launch and passes `entry = resume`; the suspended status comes from the stored try, not from the package's last exit. This is the deliberate decision-6 exception. Database coverage lands in PR 10 (1.2 unfinished exit resumes, 2004 `normal` exit starts fresh).
8. **Module swaps commit before the next launch reads.** The spike menu calls commit and terminate synchronously before swapping the iframe `src`, and synchronous commits block until the stub answers, so the outgoing module's final save lands first. This ordering is another reason async mode stays off: with async commits the swap would need `whenCommitsSettled` before navigating.
9. **Edge caching is docs-verified, live run is PR 9.** `caches.default` with `cache.put` on a miss, keyed by storage path plus an `anc` hash with the token checked first, matches the documented R2 pattern; the Cache API requires a custom domain or route, which the content domain satisfies. Immutable versions carry `Cache-Control: public, max-age=604800, immutable`, so the second request is a `HIT`. Cacheable file cap is 512 MB on Free, Pro and Business, 5 GB default on Enterprise. The live `cf-cache-status: HIT` check needs the deployed Worker and is a PR 9 test.

## Pinned dependency

`scorm-again@3.4.6` (MIT). Upgrade only after re-running the spike player against every fixture and re-checking question 6, since LMS-rule defaults are the double-application risk.
