ClassroomIO · Prototype + PRD handoff

Video Library

Publish a standalone video — release notes, a feature walkthrough, a webinar replay — without wrapping it in a course. Publishing is a flag on the existing assets row, not a new content type: the same video gets a page at /videos/<slug>, a curated section on the org landing page, a learner Videos tab, and an embeddable widget. The engineering PRD lives at prd/video-library/README.md.

Every page has a theme toggle, realistic data, and a states row so you can flip through empty / gated / processing / 404 without leaving the screen.

What is deliberately not here.
  • No progress bar, completion tick, or certificate on a standalone video. If a video must be completed, the product answer is a lesson.
  • No playlists or series — that is what courses and programs are for.
  • No "filter by course" in the section picker. A video's course link is a usage, not a property; offering it as a filter nudges admins toward publishing paid content by accident. Usage is shown as a badge instead.
  • No members-only videos, no comments, no slug redirects, no publishable documents or images.

Fidelity notes. App pages use app-theme.css, mirroring packages/ui/src/index.css (OKLCH, Geist, --radius: 0.625rem). Public pages use landing-theme.css, mirroring the default minimal org-landing theme's --landing-* variables from theme-vars-base.ts. The video-specific recipes live in video-proto.css (app) and video-landing.css (public) — the public one reads only --landing-*, which is exactly what lets one videos.svelte serve all 11 themes.
